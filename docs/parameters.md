# Template parameters

Six placeholders live in `template/` files. Run the sed script in
[`../README.md`](../README.md) to replace them all at once, or substitute
manually if you only need a few.

| Placeholder | Device baseline (v0) | Where it lives | Notes |
|---|---|---|---|
| `{{APP_NAME}}` | `open-platform-device` | `template/package.json` `name`, lifecycle log messages, generated Standalone basename, `APP_NAME` log prefix | Must be kebab-case. Standalone dev's basename is `/<{{APP_NAME}}>` (Umi auto-prefix). `APP_NAME` in logs reads from `package.json#name` at runtime — no manual sync needed once the package name is replaced. |
| `{{PREFIX_CLS}}` | `device` | `template/src/components/ThemedRoot.tsx` `prefixCls=` | antd v6 DOM class prefix. Replaces `ant-*` (e.g. `ant-button` → `device-button`). Verified to propagate to portal-render components (Modal, Drawer, Popover) in device Task 13 spike. Pick a short, sub-app-specific token — typically the same root as `{{APP_NAME}}` (e.g. `device`, `engagement`, `console`). |
| `{{CSS_VAR_PREFIX}}` | `op` | `template/src/components/ThemedRoot.tsx` `cssVar.prefix=` | antd v6 cssVar hash namespace. Default `op` matches master so design tokens stay consistent across sub-apps. Don't change unless you want a separate cssVar namespace (rare). |
| `{{YAPI_CATEGORY}}` | `3298` | `template/ytt.config.ts` `categories[0].id` | YAPI category id for the sub-app's API. Each sub-app gets its own category (device=3298, console-engagement=3316, etc. — confirm with the YAPI admin). `pnpm generate:api` reads this. |
| `{{YAPI_PROJECT_ID}}` | `144` | reserved (not in `template/` config by default) | YAPI project id. Currently the YAPI token alone authenticates against the project, so this placeholder is **reserved**: only substitute it if your sub-app needs explicit project-id config (e.g. multi-project token, custom YAPI integration script). Keep it as `{{YAPI_PROJECT_ID}}` in the template if unused. |
| `{{LOCALE_NS}}` | `page.device-` | `template/src/locales/zh-CN.ts`, `template/src/locales/en-US.ts`, `template/src/pages/index.tsx`, `template/src/pages/$id.tsx` | Locale key namespace prefix. Convention: `page.<sub-app>-<page>.<field>`. Examples: `page.device-list.title`, `page.engagement-overview.placeholder`. The trailing `-` is required so concatenating page name + field stays unambiguous. |

## Sed replacement (full template)

The script in `README.md` covers all six placeholders. After running it,
verify:

```bash
# 0 hits expected
grep -r '{{' . 2>/dev/null --include='*.ts' --include='*.tsx' \
  --include='*.json' --include='*.css' --include='*.md' --include='*.yml'
```

If `{{YAPI_PROJECT_ID}}` is intentionally unreplaced, exclude it:

```bash
grep -r '{{' . --include='*.ts' --include='*.tsx' --include='*.json' \
  | grep -v 'YAPI_PROJECT_ID'
```

## Things the template does NOT parameterize

Intentional non-parameters — change manually after scaffolding:

- **`docs/`** — sub-apps write their own docs (the template's `docs/` is for
  template users, not generated into the sub-app).
- **README.md** — replace with the sub-app's own product README.
- **`.env.local`** — never committed. Each sub-app sets its own `YAPI_TOKEN`
  and `UMI_APP_ARMS_ENDPOINT`.
- **`mock/index.ts`** — generic placeholder; replace with the sub-app's
  actual mock handlers.
- **`src/types/api/`** — not in template (don't commit generated types).
  Generated by `pnpm generate:api` after replacing `{{YAPI_CATEGORY}}`.
- **`src/styles/tokens.json`** — design tokens come from `platform-design`
  upstream. If `platform-design` changes, re-derive don't edit by hand.
